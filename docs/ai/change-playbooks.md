# AI 变更手册

## REST API 或共享契约

1. 在 `packages/shared/src/index.ts` 增加或修改请求/响应类型。
2. 需要 Fastify 运行时校验时同步 `packages/shared/src/schemas.ts`。
3. 先运行 `npm.cmd run build -w @mystry/shared`。
4. 在 `apps/server/src/services/` 实现业务逻辑，在 `routes/` 做认证、schema 和 HTTP 映射。
5. 在 `apps/web/src/api.ts` 或对应页面接入，并提供用户可见入口、加载态和错误反馈。
6. 同步 `docs/api.md`、当前状态及必要的架构决策。

不得只完成后端路由就把功能标记为“已完成”。

## 文件、上传、下载或 ZIP

1. 复用现有实例路径解析、根目录和 ownership marker 校验。
2. 保留大小、并发、空闲超时、取消和临时文件清理边界。
3. 下载端到端使用流；不得在服务端或浏览器整包缓冲大文件。
4. 添加目录逃逸、根目录操作、容量耗尽、超限和取消的负向验证。
5. 人工验证真实实例目录，不对仓库 `data/` 中的用户数据做破坏性测试。

## 数据库

1. 先说明旧 schema、目标 schema 和升级路径。
2. 使用事务或可重试步骤，失败后不得留下半迁移状态。
3. 更新行类型、查询、共享响应和用户文档。
4. 用旧数据库副本演练升级；不得直接拿用户唯一的 `panel.db` 测试。

## 进程、任务、控制台或关闭流程

1. 核对状态锁、AbortSignal、超时、子进程树和关闭顺序。
2. 区分 SQLite 任务记录与内存 worker；重启恢复必须显式设计。
3. 保持 WebSocket ticket、背压、速率和缓冲限制。
4. 验证重复启动/停止、退出竞争、EPIPE、超时、取消和面板关闭。
5. 任务 UI 对 `pending` 做持续轮询，对 429 做退避，直到终态。

## UI 与交互

1. 保持用户可见文案和代码注释为中文。
2. 接入真实 API，不用静态按钮或假数据声明完成功能。
3. 覆盖加载、空数据、失败、禁用和窄屏状态。
4. 视觉改动至少验证桌面和移动宽度、键盘焦点及可读性。
5. 构建通过后仍需在整合页面验证实际交互。

## 配置与 PanelManager

1. 新环境变量同时更新 `config.ts`、`.env.example`、配置文档和机器事实。
2. 密钥变量使用现有 64 位十六进制校验，不写固定生产值。
3. PanelManager 的 `.env` 修复必须先备份，日志不得打印密钥。
4. 关闭接口只能接受有效 `X-Launcher-Token` 且限制为回环来源。
5. Windows PowerShell 脚本保持中英文用户提示一致。

## 文档与知识库

1. 从 [文档中心](../README.md) 找到对应正文，核对源码、配置、共享契约、前端入口和测试。
2. 在正文维护操作步骤和默认值；`docs/wiki/` 只保留导航，避免复制第二份说明。
3. 历史审查、计划和验证结果保留日期与适用范围；不把分支提交数、远程发布状态或旧审计结果写成长期有效事实。
4. Windows 示例使用 `npm.cmd` 与 `.\PanelManager.cmd`；配置模板复制仅用于首次配置，不引导覆盖已有文件。
5. 运行 `knowledge:check` 与 `knowledge:test`，额外核对标题锚点和阅读路径；提交前运行 `verify`。配置、路由、脚本或 AI 入口变化时同步机器事实。

## 完成声明

交付时分别报告：

- 已实现：实际改动的链路。
- 已验证：命令、测试或人工步骤及结果。
- 未验证：当前环境无法覆盖的行为。
- 剩余风险：警告、依赖审计、兼容或运维事项。
