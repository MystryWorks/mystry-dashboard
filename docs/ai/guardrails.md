# AI 开发安全禁区

## 工作树与 Git

- 开工前检查 worktree、index、untracked 文件和当前分支。
- 用户已有修改只读保护；不得顺手格式化、回退或纳入本任务提交。
- 未经明确授权，不执行 push、force push、rebase、reset、删除分支或删除备份。
- 需要撤回已提交工作时优先保留历史的 `git revert`；历史改写必须先确认边界和远端旧 SHA。

## 密钥与运行数据

- 不读取或输出 `.env` 的密钥值；只在必要时确认变量是否存在。
- 不提交 `.env`、`data/`、`*.db`、上传、日志、构建产物或机器绝对路径。
- `JWT_SECRET`、`SETUP_TOKEN`、`LAUNCHER_TOKEN` 必须使用不同的 64 位十六进制随机值。
- 示例、测试和文档不得包含可直接投入生产的固定密钥。

## 路径与文件

- 所有实例文件操作必须走 `file-service` 和 `apps/server/src/utils/path.ts` 的现有校验。
- 不接受客户端传入的系统绝对路径、Java 可执行路径或任意安装目录；Java 只可引用面板扫描、注册并复验后的运行时 ID。
- 不绕过 symlink/junction、实例根目录、ownership marker 和 legacy 迁移保护。
- 删除、覆盖、解压和接管前必须确认目标位于 `DATA_DIR/instances/<id>`。
- 大文件下载保持流式传输；浏览器端不得用 `res.blob()` 将完整文件载入内存。

## 数据库、任务与进程

- schema 变更必须为已有 `panel.db` 提供兼容或一次性迁移，并设计失败回滚。
- 不把 SQLite 中的任务记录等同于可恢复 worker；队列和运行状态目前仍是内存态。
- 启停、重启、强杀、关闭面板必须尊重现有状态锁、取消信号和清理顺序。
- 控制台改动不得移除 ticket、连接数、帧大小、命令速率、stdin 背压或历史缓冲边界。
- 远程节点开关关闭时，不得加入绕过开关的执行路径。

## 结论和证据

- 提交标题、路由存在、类型通过、构建通过分别只是局部证据。
- 安全自检不覆盖依赖供应链；依赖是否安全必须以当前官方 registry 审计为准。
- 无法运行人工流程时必须明确写“未验证”，不能用推测替代。
- `.slim/deepwork/**` 是历史草稿；只可用于理解背景，不可直接列为当前缺陷。
