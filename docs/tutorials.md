# 分步教程

本文用「照着做就能完成」的方式，覆盖最常见的使用场景。若你尚未安装面板，请先阅读 [快速开始](getting-started.md)。

---

## 教程 1：第一次开服（推荐 Paper）

适合：本机第一次用面板，想快速开一个可联机的小服。

### 1. 配置、启动面板并初始化

1. 复制 `.env.example` 为 `.env`。
2. 分别执行两次以下命令，把两次输出填入 `JWT_SECRET` 和 `SETUP_TOKEN`；两个值必须不同。不要使用固定示例密钥：

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. 安装适配服务端的 Java；`java -version` 可检查默认 PATH 运行时，也可稍后在面板中探测其他已安装运行时。
4. 按 [快速开始](getting-started.md) 启动后端与前端（或生产模式只开 `npm start`）。
5. 浏览器打开：
   - 开发：`http://127.0.0.1:5173`
   - 生产：`http://127.0.0.1:3000`
6. 首次初始化请求必须带 `X-Setup-Token: <SETUP_TOKEN>` header；填写用户名与至少 12 位密码，创建管理员。
7. 创建成功后从 `.env` 移除 `SETUP_TOKEN`，重启面板；之后使用「登录」。

setup 仅在用户表为空时可用。

### 2. 一键部署 Paper

1. 左侧点击 **「一键部署」**（或在实例总览页右上角 **「一键部署」**）。
2. 填写表单：
   - **实例名称**：例如 `我的生存服`。
   - **核心类型**：选 **Paper**（性能与插件生态较好）。
   - **游戏版本**：在下拉框中选择目标版本（可滚动加载更多版本）。
   - **Paper Build**：一般保持默认最新 build 即可。
    - **JVM 设置**：先选最大内存和优化方案；默认兼容档只生成内存参数，高级区再填写附加参数。
    - **Java 运行时**：默认使用 PATH 中的 `java`；需要其他版本时点「重新探测」后选择，不可手填路径。
   - 勾选 **「自动接受 Mojang EULA」**（首次开服需要）。
3. 面板会自动把实例创建在 `DATA_DIR/instances/<id>`，不能改成其他目录。
4. 点击 **「开始部署」**，等待进度条到 100%。
5. 完成后会自动跳转到该实例的 **控制台** 页面。任务可能先排队，前端会持续显示状态直到完成或失败；不要因 `pending` 重复提交。

部署和运行默认使用 PATH 中的 `java`，也可选择面板扫描并验证的本机运行时；不需要填写 Java 路径或选择安装目录。

> Forge / NeoForge 部署步骤类似，但会下载官方 Installer 并执行安装，耗时更长，见 [教程 4](#教程-4部署-forge-或-neoforge-模组服)。

### 3. 启动服务端

1. 若部署后未自动启动，在实例页顶部点击 **「启动」**。
2. 观察 **控制台** 输出，直到出现类似 `Done (xx.xxxs)! For help, type "help"`。
3. 状态徽章应变为 **「运行中」**。

### 4. 本机进游戏测试

1. 打开 Minecraft，版本需与 **游戏版本** 一致（Paper 服用对应原版版本进服）。
2. 多人游戏 → 添加服务器 → 地址填 `127.0.0.1` 或 `localhost`。
3. 若无法连接，到 **「配置」** 页检查 `server-port`（默认 25565），并确认本机没有其他程序占用该端口。

### 5. 让朋友联机（同一局域网）

1. 在 **「配置」** 页确认 `online-mode=true`（正版验证）或按你需要修改。
2. 告诉朋友你的 **局域网 IP**（如 `192.168.1.100`）和端口（默认 `:25565`）。
3. 朋友在游戏里添加服务器：`192.168.1.100:25565`。

从外网访问需要路由器端口映射或内网穿透，本面板不自动处理，需自行配置网络。

## 教程 2：导入已有的 zip 服务端

适合：你已从别处下载整包服务端，或自己打包了 `server.jar` + 配置 + 世界。

### 1. 准备 zip

- 格式：**zip**（不是 rar / 7z）。
- 大小：不超过约 **512 MiB**，并遵守 ZIP 条目和解压配额。
- 内容：应包含可运行的服务端 jar（面板会自动探测，常见名为 `server.jar`、`paper.jar` 等）。
- 若 zip 里只有**一层文件夹**（例如 `myserver/server.jar`），导入后会自动「展平」到实例根目录。

### 2. 上传导入

1. 侧栏 **「导入已有服务端」**，切换到 **「上传 ZIP」**。
2. 选择 zip 文件，点击 **「上传并预检」**。文件超过大小上限返回 413；上传处理或预览容量已满返回 429。
3. 预检成功后填写 **实例名称**、核心和 Minecraft 版本。
4. 若检测到 `user_jvm_args.txt`，明确选择 **沿用检测参数 / 使用面板推荐 / 自定义配置**；解析失败时不能沿用。
5. 选择 Java 运行时和 JVM 优化方案，按需勾选 EULA（若包内尚无 `eula=true`）。
6. 点击 **「确认配置并导入」**，等待后台任务完成。队列满时预览会保留，可稍后重试确认。

导入目标自动为 `DATA_DIR/instances/<id>`；表单不能指定其他目录。未选择 Java 运行时时使用 PATH 中的 `java`，也可直接绑定面板已探测并验证的运行时。待确认预览默认保存 30 分钟，刷新页面可恢复；取消、过期或面板重启会删除临时 ZIP。

### 3. 导入后检查

1. 进入实例 **「设置」**，确认 **Jar 文件名** 与目录里实际 jar 一致。模组服 jar 名可能不是 `server.jar`，以探测结果为准。
2. **「文件」** 页可查看 `mods`、`config` 等是否完整。
3. **「启动」** 并在控制台看日志；若报 Java 版本错误，安装匹配版本并配置为默认 PATH，或在「设置」中重新探测后绑定该版本。

## 教程 3：改端口、难度与可见性（server.properties）

1. 进入实例 → **「配置」** Tab。
2. 常见项：
   - `server-port`：监听端口（改后需重启实例）。
   - `max-players`：最大玩家数。
   - `difficulty`：`peaceful` / `easy` / `normal` / `hard`。
   - `gamemode`：`survival` / `creative` 等。
   - `white-list`：`true` 时仅白名单玩家可进（需在控制台执行 `whitelist add <玩家名>`）。
   - `online-mode`：是否正版验证。
3. 修改后点 **「保存配置」**。
4. 实例页 **「重启」** 使配置生效（面板会提示：修改后需重启）。

也可在 **「文件」** 中直接编辑 `server.properties`，与「配置」页效果相同。

## 教程 4：部署 Forge 或 NeoForge 模组服

1. **「一键部署」** → 核心类型选 **Forge** 或 **NeoForge**。
2. 选择 **游戏版本**，再选对应的 **Forge / NeoForge 版本**（Loader 下拉框）。
3. 页面会提示：将下载官方 Installer 并在 `DATA_DIR/instances/<id>` 执行安装，**耗时可能较长**，请保持网络畅通。
4. 部署完成后在 **「文件」** → `mods` 文件夹上传模组（需先 **停止** 实例）。
5. 启动后若缺依赖，控制台会报错，按模组说明补装依赖或换兼容版本。

**Java 版本**：高版本 MC（如 1.20.5+）通常需要 **Java 21**；1.17–1.20.4 多为 **Java 17**。请安装匹配 JDK；可将其放入 PATH 作为默认，或在部署表单选择面板探测到的版本。

## 教程 5：用控制台管理玩家与权限

在实例 **「控制台」** 中，输入命令后 **回车** 发送（与游戏内控制台相同）。

| 目的 | 示例命令 |
|------|----------|
| 给玩家管理员 | `op 玩家名` |
| 踢出玩家 | `kick 玩家名` |
| 保存世界 | `save-all` |
| 白名单 | `whitelist on` / `whitelist add 玩家名` |
| 查看帮助 | `help` |

控制台会保留最近的输出，大小受 `MAX_CONSOLE_BUFFER_BYTES` 限制；刷新页面重连后会先看到历史缓冲。控制台最多 20 个并发连接，单条命令最多 4096 字节，每 60 秒最多 60 条命令，入站消息最多 4352 字节，stdin 待处理输入最多 65536 字节。

## 教程 6：上传地图或插件

### 上传文件到实例目录

1. **停止** 实例（修改世界或大型文件时建议先停服）。
2. **「文件」** Tab → 进入目标目录（如 `world`、`plugins`、`mods`）。
3. 点 **「上传」** 选择本地文件。
4. **「新建文件夹」** 可创建子目录。
5. 点击 **📄 文件名** 可在右侧编辑文本（如 `ops.json`、部分配置）。
6. 完成后 **「启动」** 或 **「重启」**。

文件页只能操作当前实例根目录，不是全盘文件管理器。

### Paper 插件

- 将 `.jar` 插件放到 `plugins` 目录（需 Paper 核心，不是纯 Vanilla）。

## 教程 7：管理多个实例

1. **实例总览** 列表每约 3 秒自动刷新状态。
2. 每个实例独立进程、独立端口（在各自 `server.properties` 里配置，**不要两个实例用同一端口**）。
3. 从总览可 **启动 / 停止 / 重启 / 删除**；旧版记录在完成复制后可 **接管**：
   - **删除** 会弹出确认，并删除该实例面板托管目录的全部磁盘文件，不可恢复。
   - 运行中的实例需先 **停止** 才能删除或接管。
   - 旧外部目录不会被面板访问或删除。
4. 侧栏底部可 **「退出登录」**；登录态保存在当前浏览器。

## 教程 8：备份与迁移

### 备份

复制以下内容到安全位置：

- `DATA_DIR/panel.db`（实例列表与设置）
- 每个实例的 `DATA_DIR/instances/<id>/` 完整目录

### 在同一台机器恢复

1. 停面板进程。
2. 还原 `panel.db` 与 `DATA_DIR/instances/<id>/`，保持相同的 `DATA_DIR` 和实例 ID。
3. 启动面板并检查实例列表；必要时在实例页面执行 **接管**。

### 接管面板外已有服务器

1. 在原服务器控制台执行 `stop`，等待进程完全退出。
2. 将完整服务器目录复制到 `DATA_DIR/imports/<目录名>`。
3. 在面板打开 **导入已有服务端 → 同机目录交接**，刷新并选择目录。
4. 若检测到 `user_jvm_args.txt`，先选择沿用、面板推荐或自定义，再核对核心、版本、JVM 设置和 Java 运行时，提交后等待任务完成。
5. 检查新实例的文件与端口配置，再由面板启动；原目录不会被面板删除。

### 从旧版外部目录迁移

旧版外部目录不会被面板访问、删除或自动搬迁。停止实例和面板服务后，用系统工具完整复制旧目录到对应的 `DATA_DIR/instances/<id>`，重启面板，再点击 **接管**。不要只复制世界文件或尝试在面板中选择旧目录。

### 仅迁移世界

可在实例 **文件** 页下载 `world` 内单个文件；整目录拷贝请在停止实例（必要时再停止面板）后，用系统工具复制托管实例目录下的 `world`。
